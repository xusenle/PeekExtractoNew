# 网络爬虫系统

>项目开发文档

## 一、项目简介

本项目是一套基于 Node.js 开发的**通用网页爬虫与内容解析系统**，支持网页批量爬取、自动网页推进内容提取、HTML 内容提取、本地缓存策略、内容清洗、字体图标映射纠错、自动失败重试、延迟防封机制。

项目采用分层接口，完全解耦：配置层、工具层、服务层、主调度层，代码结构规范、可扩展、可长期迭代升级。

核心目标：稳定、高效、防识别、可复用、易维护。
****

## 二、项目技术栈

- 运行环境：node.js
- 网络请求：fetch / axios
- HTML解析：cheerio
- 文件处理：原生 fs 模块封装
- 代码：原生JavaScript、Html、Css
- 架构模式：分层模块化开发

## 四、系统核心功能

1. 自动缓存系统
   - 根据URL MD5 生成唯一缓存文件
   - 支持自定义缓存过期时间(默认30分钟)
   - 缓存未过期：直接读取本地缓存文件，不请求网络
   - 缓存过期/不存在：重新爬取并更新缓存
   - 避免重复请求、防封禁、提速、省流量
2. 高防爬网络请求
   - 完整浏览器请求头模拟
   - 随机UA切换
   - 自定义延迟间隔，防高频检测
   - 失败自动重试机制
   - 超时保护，防止卡死
3. 阶段式成果展示
   - 每个阶段成果单独展示出来
   - 成果展示以页签方式呈现
   - 可以根据不同的成果进行修改
4. 网页内容分类
   - 字符串提取：自动提取网页中所有开始/结束字符串放入提取选择中
   - 选择器提取：自动提取网页中所有选择器放入提取选择中
   - 方便直接选取提取模式和提取字段
5. 双模式内容提取
   - 字符串截取模式：根据开始/结束字符串批量提取多端内容
   - 选择器模式：通过CSS选择器精确提取标签内容
   - 支持批量内容提取，不会只取第一条
   - 自动去空格、去换行、容错匹配
6. 内容纠错模块
   - 字体图标映射替换
   - 识别未映射字体列表
   - 保留原生标签结构只替换乱码内容
7. 统一错误处理机制
   - 所有工具、服务函数统一返回固定格式结果对象`{ok, data, err}`
   - 全局捕获异常，避免程序因为单个请求报错直接崩溃
   - 所有业务分支均有返回值，杜绝返回`undefined`造成的运行异常
   - 错误信息分层输出：控制台日志 + 返回给前端的提示信息
8. 文本自动保存
   - 提取完成后的处理结果支持自动保存到本地文件
   - 区分原始缓存、修改后缓存两套存储目录
   - 支持手动导出结果为文本 / JSON 格式

## 五、核心执行流程

一次完整爬取过程：

1. 接收参数：URL、延迟、重试次数
2. 检测缓存是否过期：未过期——直接调用缓存内容/过期——根据参数发起模拟请求爬取数据
3. 请求失败自动重试，达到重试次数返回失败提示
4. 爬取成功，返回爬取结果并进行缓存

爬取后文本处理过程：

1. 选择截取模式
2. 选择字体映射表
3. 选择内容清洗表
4. 批量清洗，并返回结果进行二次缓存
5. 排版清洗结果，选择导出方式

## 六、接口设计

本项目所有接口遵循 REST 简易规范，统一返回格式、统一异常处理、分层调用，前端只与路由交互，不触碰底层业务与工具逻辑。

1. 统一返回格式

   ```js
      {
      "ok": Boolean,        // 是否成功
      "data": Object|Array, // 成功返回数据
      "msg": String,        // 状态提示信息
      "err": String         // 错误详情（失败时返回）
      }
   ```

2. 核心接口列表

   - 爬虫启动接口（POST /api/crawl）
功能：接收 URL、延迟、重试次数、提取模式、映射规则，执行完整爬取解析流程
   - 缓存读取接口（GET /api/cache/get）
功能：根据 URL 获取本地缓存内容，判断是否有效
   - 缓存清除接口（POST /api/cache/clear）
功能：手动清除指定缓存或全部缓存文件
   - 缓存清除接口（POST /api/cache/clear）
功能：手动清除指定缓存或全部缓存文件
   - 文本清洗接口（POST /api/format/rule）
功能：加载自定义文本清洗规则，批量规整网页内容
   - 文件导出接口（GET /api/export/file）
功能：将处理完成的内容导出为 TXT / JSON 文件
   - 配置更新接口（POST /api/config/update）
功能：动态修改缓存时长、默认延迟、默认重试次数等全局配置

3. 接口调用链路规范

所有接口严格遵循调用单向链路：
**路由(routes)**——**控制器(controller)**——服务(service)——工具(utils)
禁止跨层调用、禁止逆向调用、禁止控制器直接操作工具函数。

## 七、开发规范

1. 目录分层规范
   1. routes：只写路由分发，不写业务逻辑、不写文件操作
   2. controllers：只做参所检验、调用服务、返回结果，不写底层逻辑
   3. services：只写核心业务逻辑，不处理HTTP响应
   4. utils：只写通用工具，纯函数、无业务、无路由依赖
   5. config：所有常量、路径、时效、配置统一存放，禁止代码硬编码
2. 代码编写规范
   1. 所有工具函数、服务函数统一返回{ok, data, err}结构
   2. 所有异步操作必须使用async/await，禁止嵌套回调
   3. 所有文件读写、网络请求必须捕获异常，杜绝程序崩溃
   4. 变量、函数命名语义化，采用驼峰命名
   5. 新增功能必须新增函数，禁止重复使用旧函数
3. 缓存与文件规范
   1. 所有文件读写必须使用封装工具类操作，禁止使用默认fs操作
   2. 缓存文件命名采用操作名称+缓存时间，不进行加密
   3. 区分提取缓存、截取后缓存、清洗后缓存
4. Git提交规范
   1. 提交忽略：缓存目录、日志、依赖包、配置隐私文件
   2. 每次提交功能单一，描述完整，禁止混合批量提交
